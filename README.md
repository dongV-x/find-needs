# 找需求

一个给业务同事使用的 Agent Skill：拿最近一次真实工作对照现有系统，找出符合实际、不符合实际和系统遗漏的内容，再整理成可以交给开发的 `需求交接.md`。

它适合已经有系统、原型或页面，需要继续核对真实工作并补充需求的阶段。业务同事不需要会写 PRD，也不需要学习产品术语；Agent 会始终使用大白话，一次只问一个问题。

任务页面可以直接触发本 Skill，不要求业务同事额外输入调用命令。Agent 必须先安装并验证本 Skill 已加载；验证失败时不能开始访谈，也不能用任务页面内容替代 Skill 流程。

## 一键下载

[下载最新 ZIP](https://github.com/dongV-x/find-needs/archive/refs/heads/main.zip)

公开仓库无需 GitHub 账号即可浏览和下载。

## 让 Agent 自动安装

把下面整段发给 Codex 或其他支持 Agent Skills 的 Agent：

```text
请安装这个 Agent Skill：
https://github.com/dongV-x/find-needs

请安装到你的用户级 Skills 目录，Skill 名称保持为 find-needs。
安装完成后告诉我安装路径，并提醒我是否需要新开对话。
先不要开始提问或调研。
```

也可以手动安装到 Codex：

```bash
git clone https://github.com/dongV-x/find-needs.git ~/.codex/skills/find-needs
```

安装完成后如当前会话无法识别新 Skill，Agent 必须明确指导业务同事重新启动或新开支持 Skills 的会话，再次发送任务链接；在此之前不得开始访谈。

## 第一次使用

系统负责人先准备一个小场景、相关页面链接和当前等待验证的内容，再把任务提示词交给业务同事。不要一次调研完整系统。

```text
这次只研究一件事：[用一句大白话说明要走通的工作]。
系统地址：[链接]
重点页面：[只列直接相关页面]

请先让我讲最近一次真实发生的情况，再让我对照页面实际操作。
找出哪些地方符合实际、哪些地方不符合、哪些平时会做但系统里没有。
如果聊到其他场景，先记到“待回看”，继续当前场景。

结束前请先用不超过 6 条大白话让我确认你没有理解错，
确认后生成“需求交接.md”。
```

完整任务单模板见 [`references/task-brief.md`](references/task-brief.md)，试用方法见 [`evals/tryout.md`](evals/tryout.md)。

## 它会处理什么

- 对方不会表达：从最近一次真实工作开始，一次只问一个容易回答的问题；
- 当前页面可能不对：把当前实现当作待核对内容，不当作业务真相；
- 突然跑题：先记录到“待回看”，再回到当前场景；
- 链接打不开：明确标记未读取，不凭标题猜内容；
- 多人说法不同：并列保留，不替团队决定规则；
- 提到旧表格或飞书文档：追到具体资料和对应工作步骤，飞书保留链接，本地脱敏文件随交接返回；
- 聊到一半暂停：保存已确认、未确认和下次继续的位置；
- 开发后复看：沿用原来的真实案例，只检查问题是否解决。

## 验证

```bash
node evals/smoke-check.mjs
```

当前测试覆盖 15 种常见回答、首次深挖、定向补问、开发后复看，以及红人营销和反馈系统两类任务卡。

## 边界

- 不替业务人员确认事实，也不把个人习惯自动写成团队规则；
- 不索要密码、验证码或登录凭据；
- 未经明确授权，不复制、上传或打包业务资料；
- 原始手机号、地址、合同金额等敏感内容应先脱敏；
- 不直接设计技术架构、数据库或代码。
