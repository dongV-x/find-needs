# 小白沟通与异常处理

只有进入实际访谈、补问或复看时读取。

## 开场

不要介绍方法论。把任务单里的“这次只想走通”改成一句人话后，用下面的形状开始；不要把示例中的业务名硬套到其他项目：

```text
这次我们只看一件事：[用任务单的一句话说明起点、要做的事和结束结果]。

不用讲完整制度。先想最近一次真的发生过的情况：这件事当时是因为什么开始的？
```

上面是通用开场。若任务单确实是红人营销场景，才可以说“最近一位达人”；其他项目应使用自己的业务对象和日常说法。

每轮使用一个小循环：

1. 用一两句话复述刚得到的事实，让对方容易纠正；
2. 只补当前最影响理解的一点；
3. 问一个具体问题；
4. 把其他想法留在内部记录，不同时追问。

## 把难词换成人话

| 避免直接说 | 优先说 |
|---|---|
| 建档 | 把这个达人记进系统 |
| 查重 | 先看看团队以前有没有记过或联系过 |
| 认领 | 确定现在由谁负责联系 |
| 保护期 | 这段时间先由当前同事负责，其他人不要重复联系 |
| 开发状态 | 目前聊到哪一步 |
| 字段 | 平时需要记下的信息 |
| 状态流转 | 事情从这一步变到下一步 |
| 异常流程 | 不顺利或临时变化时怎么办 |
| 权限 | 谁能看、谁能改 |
| 数据迁移 | 把以前表格里的资料搬进来 |

内部整理可以使用结构化术语，但不能拿术语考业务人员。

## 两轮核对

### 先讲真实工作

第一遍不打开功能清单逐项确认。沿最近一次真实案例，自然补齐：为什么开始、实际做了什么、用了什么资料、找过谁、怎样知道完成、出错或改期怎么办。

对方讲不清时，从最容易回忆的一步继续，不要求按标准顺序回答。

### 再看现有系统

让对方对照指定页面重走刚才的关键动作。每个差异至少记录：

- 当时想做什么；
- 在哪个页面或窗口；
- 当前系统出现什么结果；
- 实际工作希望怎样；
- 有什么真实案例或资料支持。

完成核对后，再问一句开放但有边界的问题：

```text
只看刚才这段工作，还有哪一步是你平时会做、但这个系统里完全没有的？
```

## 常见回答

### “我不知道怎么讲”

降低负担，不换一种专业问法继续追问：

```text
没关系，你不用讲流程。只想最近一位你真的联系过的达人：你最早是从哪里看到他的？
```

仍然卡住时，给一句暂定理解供纠正：

```text
我先猜一句，只是帮助你回忆：你通常先在平台看到达人，再去现有表格里搜一下有没有同事记录过。哪一处不对？
```

### “经常”“偶尔”“很多”这类量词

不反驳，也不照单全收，用最近的时间段把它变成数字：“上周大概碰到几次？”“上一次是什么时候？”答不出精确数字没关系，记录“每天都有 / 每周几次 / 一个月一两次”这个量级即可。量级会写进交接文档，用于后续排优先级。

### “都挺好”“差不多”

不要强行找问题，也不要立即结束。请他拿真实案例完成一次关键操作；走通后可以确认当前场景无需修改。

### 回答很长或语音转写混乱

不要逐句拆问。先用两三条复述，只选择最影响当前场景的一点确认。听不清的人名、数字和规则必须标为不确定，不自行修正。

### 突然提出另一个功能

```text
这个想法我先记到“待回看”，它属于后面的寄样环节。这次先把发现达人到开始联系走通。刚才你说会先查表格，那张表你通常搜什么信息？
```

若新信息会推翻当前理解，则先修正，不归入待回看。

### 闲聊或短暂离题

简短回应即可，然后用当前案例中的一句事实自然接回。不要训斥，不说“请回答上一题”。

### 明确要求换话题、暂停或结束

立即停止。输出当前已确认、还不确定、下一次从哪里继续。不得借收尾继续补问。

### “这不是我负责的”“我不知道”

记录谁可能知道、为什么影响当前场景、是否阻塞开发；继续对方熟悉的部分，不逼他代答其他岗位。

### 与材料或其他人员冲突

并列保留双方说法，只问一个能判断适用范围的问题。仍无法确定就交给负责人，不按职位高低自动覆盖。

### 用户直接提出解决办法

先确认他想减少的真实麻烦。解决办法可以作为建议记录，但不能因为用户说“自动化、AI、增加按钮”就直接成为已确认需求。

### 提供旧表格或资料

先读取已有内容，不询问表格已经回答的事实。只围绕当前场景核对实际用到的信息：为什么记、从哪里来、谁维护、什么时候用、空着怎么办。不要为了完整逐列盘点。

### 页面或链接打不开

明确说明未读取，提供最低负担替代：请对方截当前页面、口述刚才点击后的结果，或在获得权限后继续。未读取的链接不能作为已确认内容。

### 涉及敏感资料

请对方使用脱敏样例；不要求提供达人住址、联系方式、合同金额等与当前问题无关的内容。不得把密码、验证码或访问令牌写进记录。

## 中断与恢复

对方表示晚点继续或会话即将结束时，输出：

```text
目前已经讲清：……
还没讲清：……
下次只从这里继续：……
```

恢复时先读取旧交接或以上记录，用三句话以内回看，不从头提问。

## 结束确认

最终文档生成前，用不超过 6 条人话复述本轮关键结论，让业务人员纠正。对方确认后记录“受访人已确认本轮总结”；未确认则如实记录，不把沉默当确认。
